C. RUNTIME MATERIALIZATION MAP

materialization entrypoint
- `crates/mimir-cli/src/vertical_slice_test_support.rs::fixture_from_persisted_input(...)`

persisted anchor hint -> runtime anchor hint
- source:
  - `artifact.payload.anchor_hint`
- destination:
  - `mimir_anchor::AnchorHint`
- exact field mapping:
  - `anchor_id -> anchor_id`
  - `frame_index -> frame_index`
  - `kind -> kind`
  - `metadata -> metadata`
- runtime use:
  - passed into `HintAnchorDetector.detect_persisted(...)` through `run_deterministic_vertical_slice(...)`

persisted proposals -> runtime proposal fixture / branch proposal
- source:
  - `artifact.payload.proposals`
- destination outer wrapper:
  - `Vec<VerticalSliceProposalFixture>`
- destination inner proposal:
  - `mimir_branch::BranchProposal`
- exact mapping per proposal:
  - `label -> branch_proposal.label`
  - `actions -> branch_proposal.actions`
  - `legal_hint -> branch_proposal.legal_hint`
  - `metadata -> branch_proposal.metadata`
  - `score_signals -> VerticalSliceProposalFixture.score_signals`
- runtime use:
  - `branch_proposal` values feed `BoundedManualBranchGenerator`
  - `score_signals` feed `score_branch(...)`

persisted score_signals -> scorer input
- source:
  - `VerticalSliceProposalFixture.score_signals`
- runtime consumer:
  - `crates/mimir-cli/src/vertical_slice.rs::score_branch(...)`
- exact call:
  - `WeightedSumScorer::score(Some(branch_id.clone()), score_signals)`
- implication:
  - proposal-local score component values remain lane-defined and are not inferred anywhere else

persisted scorer_weights -> runtime scorer_weights
- source:
  - `artifact.payload.scorer_weights`
- destination:
  - `VerticalSliceFixture.scorer_weights`
- runtime consumer:
  - `WeightedSumScorer::new(fixture.scorer_weights.clone())`

header metadata / fixture lane identity handling
- persisted header metadata does not alter runtime scoring, anchor generation, or branch generation
- current lane identity is carried by:
  - header metadata key `fixture_lane`
  - the explicit constructor match arm in `persisted_input_artifact_for_lane(...)`
- fixture identity is therefore still explicit in test-support code, not discovered via a registry

other top-level field mappings
- `replay_id -> VerticalSliceFixture.replay_id`
  - then into `HintAnchorDetector.detect_persisted(...)`
- `export_name -> VerticalSliceFixture.export_name`
  - then into export manifest identity and teacher-label ids
- `teacher_namespace -> VerticalSliceFixture.teacher_namespace`
  - then into teacher synthesis request namespace and teacher artifact metadata
- `simulation_seed -> VerticalSliceFixture.simulation_seed`
  - then into `SimulationRequest.seed` for every generated branch simulation request
