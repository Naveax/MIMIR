what was intentionally excluded

- guessed contact, detach, landing, or stable-control semantics
- any parameter derived from real replay parsing beyond the canonical frame window
- rollout-backed scores, feasibility scores, or confidence scores
- generic family-independent parameter containers
- optimizer/search loops
- metadata escape hatches
- curriculum/export/runtime fields

whether Rust type shaping and narrow implementation were added, and why
- Yes.
- Added shared DTO-style contracts in `crates/mimir-types/src/lib.rs` because the parameter bundle
  and generated variants are plain cross-crate data boundaries that later validator or export work
  may consume.
- Added narrow solver/variation logic in `crates/mimir-skill/src/lib.rs` because deriving the
  bounded parameter surface and deterministic family-specific variants is Skill Forge logic, not a
  generic type-only concern.
- The implementation validates canonical bundle consistency before solving so later stages are not
  handed structurally contradictory provenance.

why this is enough for the next validator + confidence/abstain pass
- The next pass now receives a bounded parameter contract rather than a vague canonical bundle.
- The next pass can measure whether one exact observed window or one-frame boundary trims survive
  validator checks without pretending those trims are proven truths.
- Confidence/abstain logic can now distinguish:
  - malformed canonical boundary
  - structurally valid parameter seed
  - validator rejection of exact or trimmed variants
- No generic search infrastructure was introduced, so validator work remains narrowly attached to
  low boost recovery rather than reopening whole-framework scope.
