## G. DECISION

The decision in v1 is:

- Outcome A: a new reopen-decision artifact is needed before naming the next contract

### Why Outcome A is the honest choice

Outcome B is not honest yet because freezing a contract-definition boundary now would require
choosing an explicit input form that the audited repo does not actually expose. That would force
the pass to invent at least one unproven semantic:

- the carrier/source form itself
- the storage/provenance form itself
- the admission transport itself
- or the reason a sidecar/manifest/artifact/input-surface must exist

Outcome C is too weak because the blocked explicit-admission realization already gives enough
truthful structure to define a narrower next boundary question than the repo had before this pass.

So the minimum honest next boundary above the blocked explicit-admission realization is:

- another reopen-decision boundary focused only on determining the minimum honest explicit
  externally admitted carrier provenance/source-binding source form

That is narrower than a new contract-definition pass because it still does not choose whether the
future explicit input must be:

- a new family-specific artifact
- a new family-specific sibling file or sidecar
- a new family-specific manifest/index entry
- a new explicit caller-supplied surface in `mimir-skill`
- or some other still-unproven low-boost-recovery-specific source form

### Why parser-related work is still downstream and forbidden

Replay parsing is still downstream because the repo still lacks any honest way to produce or admit
an explicit replay-source binding above the blocked explicit-admission realization.

That means the repo still lacks every prerequisite parser work would need here:

- no replay path admitted by contract
- no replay bytes admitted by contract
- no replay frames admitted by contract
- no actual `mimir_replay::ReplayInput` admitted by contract

So replay parsing remains downstream and forbidden in this pass.

### Why `source_replay`, `source_replay.provenance_label`, and the audited family root still cannot be used

`source_replay` cannot be used because it is still only `ReplaySourceRef { replay_id,
provenance_label }`, which is opaque lineage rather than a replay-source carrier contract.

`source_replay.provenance_label` cannot be used because it is still only a label string. No
audited surface in the repo binds that label to:

- a filesystem path
- a byte container
- a frame stream
- an actual `mimir_replay::ReplayInput`

`audited_family_root_directory` cannot be used because the repo still uses it only as a BC
specimen-tree anchor for receipt-bound validation. No audited surface binds it to replay storage.
