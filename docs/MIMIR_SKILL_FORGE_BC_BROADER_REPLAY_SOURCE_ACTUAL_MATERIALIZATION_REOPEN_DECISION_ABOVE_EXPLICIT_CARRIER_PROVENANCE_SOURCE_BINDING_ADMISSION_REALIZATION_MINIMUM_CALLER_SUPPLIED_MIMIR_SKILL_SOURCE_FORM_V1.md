## F. DECISION

The decision in v1 is:

- Outcome A: another reopen-decision is still required because the caller-supplied class is still
  not justified as one exact next source form

### Why Outcome A is the honest choice

The audited repo now justifies one narrower claim:

- a brand-new caller-supplied surface in `mimir-skill` is the minimum honest remaining
  source-form class

That narrower claim is justified because:

- artifact, sibling-sidecar, and manifest/index classes are already closed and remain closed
- `mimir-export` widening is still forbidden
- `mimir-io` owns raw file IO, not family-specific caller admission
- `mimir-replay` owns generic replay carrier abstractions, not receipt-bound tuple binding
- the family-specific blocked explicit-admission chain already lives in `mimir-skill`
- any new truthful external source above the blocked explicit-admission realization therefore has
  only one honest ownership location left:
  a new caller seam in `mimir-skill`

But Outcome B is still too strong because the repo does not justify one exact caller-admitted
source form yet.

Freezing an exact contract boundary now would still require inventing at least one unproven
semantic:

- whether the caller admits provenance-only binding or carrier-bearing binding
- whether the admitted source should be file-backed
- whether the admitted source should be byte-backed
- whether replay-frame-backed admission is still live above the current workspace surfaces
- whether the admitted carrier should be `mimir_replay::ReplayInput`
- how the caller-admitted payload binds to the preserved receipt-bound tuple

Outcome C is too weak because the repo does now justify a narrower audited decision than the prior
pass:

- the minimum honest remaining source-form class is now fixed to a brand-new caller-supplied
  `mimir-skill` surface
- the still-missing problem is narrower than before:
  one exact caller-admitted source form remains unresolved

## G. WHY AN EXACT CALLER-SUPPLIED FORM IS STILL NOT JUSTIFIED

The repo still does not justify one exact caller-admitted source form because:

1. No audited public DTO above the blocked realization defines the caller payload.
2. No current consumer in `mimir-skill` proves whether the minimum honest caller admission should
   be:
   - provenance-only
   - carrier-only
   - file-backed
   - byte-backed
   - `ReplayInput`-backed
3. `mimir-replay::ReplayInput` existing is not enough:
   - it is unused outside `mimir-replay`
   - it does not carry receipt-bound tuple identity
   - it does not carry provenance/source-binding semantics
4. The current explicit-admission notes intentionally refuse to promise:
   - carrier class
   - locator semantics
   - storage semantics
   - replay path
   - replay bytes
   - replay frames
   - actual `mimir_replay::ReplayInput`
5. Promoting a brand-new Rust type now would force the repo to choose payload semantics that the
   audited surfaces have not proven.

So the honest next step is still:

- another reopen-decision focused only on one exact caller-admitted source form in `mimir-skill`
