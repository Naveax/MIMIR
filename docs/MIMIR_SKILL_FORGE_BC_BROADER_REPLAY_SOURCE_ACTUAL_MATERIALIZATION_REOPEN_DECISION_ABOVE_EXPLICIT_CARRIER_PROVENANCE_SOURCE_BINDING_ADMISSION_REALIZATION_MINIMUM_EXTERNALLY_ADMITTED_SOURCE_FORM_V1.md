## A. PURPOSE

### What this pass owns

This pass owns exactly one narrower reopen-decision question above:

- `LowBoostRecoveryBcReceiptBoundValidatedSpecimenFileRawStateWindowReplaySourceActualMaterializationExplicitCarrierProvenanceSourceBindingAdmissionRealizationResultV1`

It decides only:

- whether the audited repo now justifies one exact minimum honest explicit externally admitted
  carrier provenance/source-binding source form for low-boost-recovery receipt-bound specimens
- or whether the repo can only narrow the candidate set without honestly freezing one exact source
  form yet

The candidate source-form classes considered in this pass are only:

- a caller-supplied surface in `mimir-skill`
- a new family-specific artifact
- a family-specific sibling file or sidecar
- a manifest/index surface
- or none of those yet

### Why it exists

The prior reopen decision above the blocked explicit-admission realization already proved:

- the missing gap is no longer blocked explicit-admission realization shape
- the missing gap is now the absence of any honest explicit source form that could carry an
  externally admitted carrier provenance/source binding without cheating through opaque lineage or
  the audited family root

That prior pass was still broader than necessary because it left all source-form classes open.

This pass exists to narrow that uncertainty using the current audited docs and crate surfaces
without reopening replay-source actual-materialization, replay-source carrier discovery,
replay-input locator logic, replay parsing, raw-state payload materialization, tensor/control
materialization, or `mimir_export`.

### How it differs from the previous reopen decision below it

- The previous reopen decision proved that some explicit source form is still missing.
- This pass audits whether any exact source-form class is now justified.
- This pass is still not a contract-definition boundary.
- This pass is still not a realization boundary.
- This pass is still not replay-source actual-materialization implementation.

## E. SOURCE-FORM DECISION QUESTION

The exact question is:

- which source-form class, if any, is the minimum honest explicit externally admitted carrier
  provenance/source-binding source form above the blocked explicit-admission realization?

### Evaluation of each candidate class

#### Candidate 1: new family-specific artifact

This is not justified now.

Why:

- no current artifact kind/schema exists on this defect path for replay-source binding admission
- `docs/ARTIFACT_VERSIONING.md` still restricts top-level versioned artifacts deliberately
- current low-boost-recovery BC replay-source work above the specimen file is receipt-bound
  validation inside `mimir-skill`, not persisted artifact production
- adding a new artifact family now would invent producer, schema, and reader semantics that the
  audited repo does not expose

#### Candidate 2: family-specific sibling file or sidecar

This is not justified now.

Why:

- no current low-boost-recovery emitted specimen contract defines a sibling replay-source binding
  file
- no current naming rule binds `anchored_bc_specimen_file_path` to a sibling source-binding file
- `docs/MIMIR_SKILL_FORGE_BC_ACTUAL_FILESYSTEM_EMISSION_V1.md` froze only the specimen JSON file
  contract
- the earlier emitted-output refinement decision explicitly kept sidecar/manifest semantics
  unjustified
- choosing a sibling file now would invent storage and pairing semantics

#### Candidate 3: manifest/index surface

This is not justified now.

Why:

- low-boost-recovery emitted-output docs explicitly kept manifest/index semantics out of the family
  path
- `mimir-export` manifest/index surfaces are unrelated export orchestration
- current blocked explicit-admission realization still carries receipt-bound tuple identity
  directly, not family-root reopening through a manifest
- choosing a manifest/index now would widen into exactly the semantics earlier boundaries froze

#### Candidate 4: caller-supplied surface in `mimir-skill`

This is the only remaining non-disproved direction, but it is still not justified as one exact
source form yet.

Why:

- the repo currently exposes no caller-facing seam above the blocked realization
- no existing DTO proves what exact admitted object the caller would provide
- no audited consumer proves whether the minimum honest caller admission would bind:
  - a path-like provenance carrier
  - a bytes-like provenance carrier
  - a frame-like provenance carrier
  - or a still narrower provenance-only binding form
- freezing that boundary now would still force the repo to invent payload semantics

### Most narrowed truthful answer in v1

The minimum honest source form is still:

- none of the audited source-form classes yet

More narrowly:

- new artifact is not justified
- sibling file/sidecar is not justified
- manifest/index is not justified
- a future caller-supplied `mimir-skill` surface is the only remaining candidate class, but its
  exact form is still unproven

That is narrower than the prior reopen decision because three candidate classes are now excluded by
audit, and the remaining uncertainty is localized to whether a brand-new caller-supplied seam can
be justified at all.

## F. DECISION

The decision in v1 is:

- Outcome A: a further reopen-decision is still required because no exact source form is yet
  justified

### Why Outcome A is the honest choice

Outcome B is not honest yet because naming a contract-definition boundary now would still require
the repo to invent at least one unproven semantic:

- the exact caller-admitted object shape
- the exact provenance transport semantics
- the exact binding payload semantics

Outcome C is too weak because the repo now does justify a narrower audited answer than before:

- family-specific artifact is not the minimum honest source form
- sibling sidecar is not the minimum honest source form
- manifest/index is not the minimum honest source form
- only a possible future caller-supplied surface remains live, but not yet exact

### Why parser work is still downstream and forbidden

Replay parsing remains downstream because the repo still lacks any honest exact admitted source
form above the blocked explicit-admission realization.

That means the repo still lacks every parser prerequisite that would be needed here:

- no admitted replay path
- no admitted replay bytes
- no admitted replay frames
- no admitted `mimir_replay::ReplayInput`

So replay parsing remains downstream and forbidden in this pass.

### Why `source_replay`, `source_replay.provenance_label`, and the audited family root still cannot serve as the source form

`source_replay` still cannot serve because it remains only:

- `ReplaySourceRef { replay_id, provenance_label }`

That is still lineage only, not a binding-source carrier contract.

`source_replay.provenance_label` still cannot serve because no audited surface binds it to:

- a filesystem path
- a bytes container
- a frame container
- a caller-provided binding object
- an admitted `mimir_replay::ReplayInput`

`audited_family_root_directory` still cannot serve because the current repo still uses it only as:

- a BC specimen-tree anchor

No audited surface binds it to replay storage or explicit carrier provenance/source binding.
