## A. PURPOSE

### What this pass owns

This pass owns exactly one realization boundary above:

- `LowBoostRecoveryBcReceiptBoundValidatedSpecimenFileRawStateWindowReplaySourceActualMaterializationExplicitCarrierProvenanceSourceBindingAdmissionContractV1`

It realizes only:

- the first truthful result surface above that explicit carrier provenance/source-binding admission contract
- the exact currently realizable truth when the contract carries no externally admitted explicit replay-source carrier provenance/source binding input

### Why it exists

The contract-definition boundary below this pass already froze:

- the exact receipt-bound tuple that may later receive one externally admitted explicit carrier provenance/source binding
- the exact contract-only admission kind
- the exact opacity and audited-root rules that forbid deriving replay-source semantics from opaque lineage or the family root

What remained missing was the first honest realization answer above that contract:

- can the current implementation realize a real admitted explicit carrier provenance/source binding?
- or can it only realize a truthful blocked admission result?

### How it differs from the admission contract-definition boundary below it

- The lower boundary defines the admission contract shape.
- This pass realizes the current truth above that shape.
- The lower boundary may acknowledge a future admitted explicit carrier provenance/source binding.
- This pass states that no such admitted binding is currently present in the contract input, so the truthful result remains blocked.
- Neither boundary implements replay-source actual-materialization, replay-source carrier discovery, replay-input locator logic, replay parsing, raw-state payload materialization, tensor/control materialization, or `mimir_export`.
