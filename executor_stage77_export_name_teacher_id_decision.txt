- Those Stage77 tests show that teacher ids do not drift when proposal surfaces, namespace, scoring inputs, teacher ordering, or hidden deterministic inputs change. The only named unproven point is an export-name-only mutation on Stage77.

It would add same-lane symmetry, but not an independent implementation cross-check or a new behavioral boundary.
- Because the derivation code is not lane-specific and because Stage77 already has broad same-lane teacher-artifact stability coverage, the remaining gap is mostly documentary naming, not a materially missing safety guarantee.

why the existing evidence is sufficient
- The family-level direct-effect proof exists and is narrow: mutating only `export_name` changes only export-name-derived teacher ids while preserving unrelated surfaces.
- The Stage77 lane already proves teacher ids are stable when:
  - branch payload label, actions, legal hint, and metadata change
  - teacher namespace changes
  - score signals change and teacher ordering flips
  - scorer weights change and teacher ordering flips
  - simulation seed changes
- That combination is enough to support the current family claim in the matrix: the edge is closed enough for deterministic-family closure and only partial as an intentionally not-separately-first-class Stage77 same-lane proof.

- It would reuse the same teacher-id constructor and persisted-input mutation helper pattern already proven by Stage69.
- It would not widen the trusted boundary, add an independent consumer path, or harden a distinct loader/runtime seam.
- It would primarily satisfy lane symmetry aesthetics in the matrix rather than close a different failure mode.
- Current repo-local closure summaries already warn against reopening closed deterministic-family work for symmetry alone.
