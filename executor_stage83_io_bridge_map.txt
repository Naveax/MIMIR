C. BRIDGE INVARIANTS

1. proposal order -> branch generation order
- `run_deterministic_vertical_slice(...)` zips `branch_artifacts.iter().zip(&fixture.proposals)`
- the branch generator must return the same count as proposal count
- export bundle branch order and scoreboard row order depend on this preserved proposal order

2. scorer_weights + score_signals -> scoreboard totals
- `WeightedSumScorer::new(fixture.scorer_weights.clone())`
- `score_branch(...) -> scorer.score(Some(branch_id.clone()), score_signals)`
- current visible totals:
  - Stage69: `3.5`, `5.0`
  - Stage77: `6.0`, `2.5`

3. scoreboard totals -> teacher ranking order
- `teacher_seed_label(...)` stores each branch total in the teacher seed label
- `synthesize_teacher_labels(...)` sorts labels by descending score, then by label id as a tie-breaker
- persisted teacher artifact ordinal is therefore the current ranking surface

4. export_name / replay_id / anchor identity -> frozen snapshot identity
- frozen snapshot identity currently includes:
  - `export_name`
  - `replay_id`
  - `anchor_id`
  - `anchor_frame_index`
  - `anchor_kind`
- snapshot construction requires exactly one anchor

5. simulation_seed -> deterministic repeated-run identity
- the seed is passed into every `SimulationRequest`
- no first-class output field carries the seed back out
- current contract proof is equality across two independent runs, not direct seed echo

6. fixture header metadata -> explicit lane identity only
- `fixture_lane` is documentary identity on `vertical-slice-input.json`
- it does not drive scoring, branch generation, teacher synthesis, export semantics, or snapshot materialization

7. canonical loader cardinality invariants
- export bundle branch count must equal scoreboard row count
- scoreboard row count must equal teacher artifact file count
- teacher targets must remain `TeacherLabelTarget::Branch`
- these are explicit failure boundaries, not inferred tolerances

8. frozen snapshot is intentionally narrower than canonical reload
- snapshot captures identity, branch order, scoreboard totals, and teacher target order
- snapshot does not include:
  - teacher namespace
  - anchor metadata
  - branch actions
  - branch legal_hint
  - branch metadata
  - score component breakdown
  - scorer weights
  - fixture header metadata

D. KNOWN NON-BRIDGED OR INDIRECT AREAS

- `simulation_seed` has no direct visible output field; it is only reflected by deterministic repeated-run identity.
- `scorer_weights` are not persisted back out anywhere in the output surface; they only affect totals indirectly.
- `proposal.score_signals` are not exported directly; only scoreboard score components/totals and derived teacher ranking expose their effects.
- `anchor_hint.metadata` survives in the exported anchor artifact but not in the golden snapshot.
- proposal `actions`, `legal_hint`, and `metadata` survive in export bundle branch artifacts, but not in the scoreboard, teacher artifacts, or golden snapshot.
- `teacher_namespace` is visible in teacher-label artifacts and canonical teacher artifact reload, but not in the frozen snapshot.
- input header `fixture_lane` metadata is documentary identity only, not runtime semantics.
- canonical loader does not reload `vertical-slice-input.json`; the input artifact guards the upstream boundary, while canonical reload guards the downstream artifact boundary.
